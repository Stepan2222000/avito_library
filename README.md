# avito

Сбор данных с Авито обычными HTTP-запросами: без браузера, без эмуляции интерфейса.
Страницы Авито отдаёт вместе с готовым JSON внутри, поэтому разбирать вёрстку не нужно —
данные забираются как есть.

Библиотека умеет три вещи: показать, какие у категории бывают фильтры, забрать выдачу
каталога и забрать карточки объявлений по номерам. Всё асинхронное.

## С чего начать

Полчаса чтения снимает почти все вопросы, и порядок тут важен.

**Если будете вызывать библиотеку.** Сначала этот файл целиком — особенно раздел «Что
происходит само, а что роняет задачу»: библиотека намеренно жёсткая, и это надо принять
до первого запуска, а не после. Дальше `avito/api.py`: он небольшой и это единственное
место, где решается «что делать дальше», всё остальное — исполнители. Там же описан
протокол поставщика адресов, без которого библиотека не работает вовсе. Потом
`avito/errors.py` — пять ошибок, каждая с объяснением, почему она валит задачу, а не
замалчивается. И наконец `avito/parse.py`, если нужно знать, какие поля вообще бывают:
имена полей там же, где они и собираются.

**Если будете читать базу.** Хватит `avito/schema.sql` — он написан как справочник, с
объяснением каждой неочевидной колонки. Ниже раздел «База» пересказывает его коротко и
даёт готовые запросы. Шапка `avito/store.py` объясняет правила слияния: почему карточка
не затирает то, что знает каталог, и наоборот.

## Установка

```bash
pip install -r requirements.txt
```

## Быстрый старт

```python
import asyncio
from avito import Авито, Склад

async def main():
    авито = Авито(адреса, склад=Склад())      # склад необязателен

    выдача = await авито.каталог(
        "/moskva/avtomobili",
        фильтр={"Марка": "Audi",
                "Год выпуска": (2015, 2016),      # диапазон, любая граница может быть None
                "Привод": ["Полный", "Задний"]},  # несколько значений
        страниц=2,
    )
    print(len(выдача.объявления), "из", выдача.всего)
    print(выдача.фильтр)          # «Марка: Audi; Год выпуска 2015–2016; Привод: Задний, Полный»

    карточки = await авито.карточки([8343463384])
    print(карточки.карточки[0]["заголовок"])

asyncio.run(main())
```

Фильтр задаётся словами — коды значений библиотека подставит сама, взяв их из страницы
категории. Посмотреть, что вообще бывает:

```python
спр = await авито.фильтры("/moskva/avtomobili")
спр.найти("Привод").значения     # {331253: 'Полный', 331252: 'Задний', 331251: 'Передний'}
```

## Что нужно дать библиотеке

Прокси она не ведёт: адреса приходят снаружи, потому что их учёт, качество и остывание —
отдельная задача. Нужен объект с двумя методами:

```python
class Адреса:
    async def взять(self): ...                 # вернуть адрес; None — только если их нет совсем
    async def вернуть(self, адрес, исход): ...  # «прошло», «таймер», «капча», «заглушка», «молчит»
```

Сам адрес — это `имя` для журнала и `сессия`, которая умеет `get`, `post` и хранит куки.
Сессия обязана следовать редиректам: библиотека смотрит только на конечную страницу.
Ждать ли, пока выбывшие адреса остынут, решает поставщик: библиотека просто просит
следующий адрес. По замерам таймер держится около получаса, поэтому разумное поведение —
дать выбывшему адресу столько отдыха, а если свободных нет, дождаться ближайшего.

Клиент должен быть `curl_cffi` с подделкой отпечатка (`impersonate="firefox133"`):
Авито смотрит на отпечаток TLS, и `httpx` с теми же заголовками с тех же адресов
получает блокировку. Соединение переиспользовать нельзя — Авито закрывает его после
каждого ответа, и каждый второй запрос падает; лечится `FRESH_CONNECT`.

## Что происходит само, а что роняет задачу

Само, молча: проверка безопасности решается перебором хеша за доли секунды, капча
решается без браузера, на таймере и на выпихивании адрес меняется, обрыв связи
повторяется трижды.

Роняет задачу (все ошибки наследуются от `КритическаяОшибка`):

- `НеопознаннаяСтраница` — пришло то, чего не знает ни один детектор;
- `ФильтрНеПрименился` — выдача пришла обычной, но запрошенного фильтра в ней нет;
- `ОшибкаРазбора` — разметка поехала или брака больше пяти процентов;
- `АдресаКончились` — поставщик сказал, что адресов нет совсем;
- `ОбъявлениеСнято` — объявления больше нет.

Работаем жёстко намеренно: молча вернуть половину данных хуже, чем остановиться. Недобор
превращается в «нашли двести объявлений» там, где их было пять тысяч, и заметить это
потом невозможно.

## Наблюдение

Библиотека ничего не печатает и не сохраняет. На каждый запрос она зовёт наблюдателя и
отдаёт ему событие вместе с телом страницы — складывать html и вести журнал решаете вы:

```python
def печатать(с):
    print(с.вид, с.состояние, с.код, с.адрес, с.ссылка)

авито = Авито(адреса, наблюдатель=печатать)
```

## База

`Склад` пишет в PostgreSQL. Восемь таблиц с русскими именами — читать их будут люди, а
не только код. Ключи разобранных данных те же самые, так что `объявление["цена"]` в
питоне и колонка `цена` в базе — одно и то же.

**Данные.** `объявления` — по строке на объявление, всегда самое свежее состояние.
`продавцы` — частник опознаётся ключом, магазин слагом бренда. `фотографии` — ссылки,
файлы не качаем.

**История.** `наблюдения` — цена и просмотры на каждый визит, по ним видно динамику.
`изменения` — только осмысленные события: цена, заголовок, поднятие, смена продавца.
Переход «не знали → узнали» изменением не считается.

**Журнал сбора.** `запросы` — один поиск, одна строка. Это главное, что стоит понять
про базу: страницы отдельными сущностями не считаются, и поиск на 55 страниц — всё
равно одна строка. `находки` — какое объявление на какой странице какого поиска
встретилось; только здесь живёт позиция в выдаче, потому что одно объявление находится
по разным поискам на разных местах. `обращения` — журнал походов за страницами: когда,
сколько принесли, с какого адреса.

Связаны они просто: `объявления.продавец` смотрит в `продавцы.номер`, у фотографий,
наблюдений и изменений есть `объявление`, у находок и обращений — `запрос`. Первичный
ключ всюду называется `номер`.

Два правила слияния, из-за которых источники не портят друг друга: побеждает самое
свежее, но пустотой не затираем. Каталог не знает описания, характеристик и просмотров;
карточка не знает позиции в выдаче. Каждый дописывает своё и не трогает чужое.

Что обычно спрашивают:

```sql
-- Полнота обхода: сколько Авито обещал и сколько мы забрали
select з.ключ, з.нашлось,
       (select count(*) from находки н where н.запрос = з.номер) собрано
from запросы з order by з.обновлён desc limit 20;

-- Динамика одного объявления
select когда::date, цена, просмотров_всего
from наблюдения where объявление = 8089466838 order by когда;

-- Что менялось за последние сутки
select объявление, поле, было, стало, когда
from изменения where когда > now() - interval '1 day' order by когда desc;

-- Каким поиском нашли это объявление и на какой странице
select з.ключ, н.страница
from находки н join запросы з on з.номер = н.запрос
where н.объявление = 8089466838;
```

Схема применяется сама: `await Склад().применить_схему()`.

## Разбор без сети

Если страницы уже сохранены, сеть не нужна:

```python
from avito.parse import разобрать_выдачу, разобрать_карточку

выдача = разобрать_выдачу(open("страница.html").read())
карточка = разобрать_карточку(open("объявление.html").read())
```

## Чего библиотека не делает

- **Не ходит в несколько потоков.** Одна задача — один адрес, страницы по очереди.
- **Не дробит выдачу.** Глубже сотой страницы Авито не пускает, а это около пяти тысяч
  объявлений на любой фильтр; чтобы забрать больше, срез надо резать самому — например,
  по годам или маркам.
- **Не качает фотографии.** Ссылки собирает, файлы — нет.
- **Не умеет три фильтра:** пробег, кузов и турбину. Они принимаются, но Авито их молча
  игнорирует; библиотека откажется собирать такой запрос, а не сделает вид, что всё
  хорошо. Проверено вживую, подробности — в `avito/filters.py`.
- **Не обрабатывает снятые объявления** — падает на них.

## Как это устроено внутри

- `api.py` — задачи и порядок действий, единственное место, где решается «что дальше».
- `detect.py` — семь детекторов: каталог, карточка, выдача, барьер и его три вида,
  заглушка. Каждый смотрит ровно на один узел разметки и отвечает «да» или «нет».
- `barriers.py` — преодоление барьеров. Успехом считается не «решатель доволен», а
  свежая страница без барьера.
- `filters.py` — справочник значений и сборка компактного кода `f=`, которым Авито
  передаёт фильтры. Кодировщик сверен побайтово с настоящими ссылками Авито.
- `parse.py` — разбор страниц, без сети.
- `store.py` — запись в PostgreSQL, там же правила слияния.
- `errors.py` — то, после чего продолжать нельзя.
- `schema.sql` — схема базы и переезд со старых имён.
- `geetest.py` — решатель капчи.
